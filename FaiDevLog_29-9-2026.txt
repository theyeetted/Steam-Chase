1. Cards can accidentally be duplicated
When a card is played, the current code can add it to the discard pile twice. This could cause cards to appear more frequently than intended when the deck cycles.

2. Restarting doesn't fully reset the game
The current setup process does not completely clear existing card piles and status effects. A restart or repeated setup could leave old state behind.

3. Defeat and enemy deaths need more work
The guide notes that the player's death-handling logic is incomplete. An enemy killed by Shock may also remain able to perform an attack that was already queued.

4. The opening hand has a problem
The documented startup sequence fills the draw pile but does not draw the opening hand. The first normal five-card draw is instead scheduled after an enemy turn.

5. The wrong scene is configured for launching the game
The current gameplay setup is in Tutorial.unity, but the saved build settings enable SampleScene.unity. The latter also contains an unresolved reference to an older card-view script.

Card management

Hand and status-effect resets

Enemy and energy resets
We added a way to remove old enemies and recreate them, plus EnergySystem.ResetEnergy() to restore energy.

Fight restart flow
We added MatchSetupSystem.RestartFight() to coordinate resetting the hero, enemies, deck, and energy, then draw five cards.

Action ordering
We changed the initial draw/refill sequence so the refill is requested after the draw finishes, rather than immediately submitting two actions.
